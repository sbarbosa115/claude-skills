# QA expert: use the app, find what is wrong, file it by priority

Follow the steps in `steps/` in order. Read each step file before doing that step. The project's own `README.md`,
`CLAUDE.md`, design docs and `.claude/skills/` override them where they disagree (how to run the app, which stack is
safe to use, what the design rules are).

| Step | File | Tooling |
|---|---|---|
| 1. Set up: scope, a safe stack, accounts, the run file | `steps/01-setup.md` | `scripts/qa.py init`, `scripts/qa.py run` |
| 2. Map the app into flows (first run; refreshed when views change) | `steps/02-map.md` | `templates/flow.md` |
| 3. UI/UX audit, view by view | `steps/03-design-audit.md` | |
| 4. Functional audit, view by view | `steps/04-functional-audit.md` | |
| 5. Record: one file per issue, dedupe, re-check open ones, the priority list | `steps/05-record.md` | `scripts/qa.py new\|index\|status`, `templates/issue.md` |

Steps 3 and 4 run together on each view: open it once, look at it with both eyes, then move to the next.

What lands in the project:

```
docs/qa/
  README.md              how the QA docs work, the coverage table (each view, when it was last checked)
  flows/<area>.md        how the app works, written on the first run: views, actions, rules, expected behaviour
  issues/README.md       the priority list, generated by `qa.py index` (never edited by hand)
  issues/QA-0001-<slug>.md   one issue per file, frontmatter + steps to reproduce + expected vs actual
  issues/runs/<date>-<scope>.md   one report per execution: what was covered, what was found, what was re-checked
```

Scripts live in `~/.claude/skills/qa-expert/scripts/` and run from anywhere inside the project checkout (Python 3,
standard library only).

Hard rules:

- **Find and document; never fix.** No change to application code, tests or config. The only files written are
  under `docs/qa/`. Commit them only when the user asks, on a branch, never on the default branch.
- **Never against production or real customer data.** Use the local or a disposable stack, and the seed accounts.
- **Every finding is reproduced or labelled.** A finding seen in the app has its steps; one found only by reading
  code says `confidence: code-read` and is never above P2 until it is reproduced.
- **One issue per file, one file per issue.** Before filing, search the open issues; a repeat updates the existing
  one (`last_seen`), it does not make a new one.

Report what was not covered as plainly as what was found.
